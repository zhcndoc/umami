---
title: 监控 Core Web Vitals
---

*需要 v3.1.0*

使用 Umami 了解真实访客访问网站时的体验。性能跟踪可以帮助您发现加载缓慢的页面、捕获性能回归，并确定哪些浏览器或设备需要关注。

## 第一步：启用性能跟踪

将 `data-performance` 属性添加到跟踪脚本中：

```html
<script
  defer
  src="https://your-umami.example.com/script.js"
  data-website-id="your-website-id"
  data-performance="true"
></script>
```

如果您手动发送页面浏览，请保持自动跟踪启用，并添加 `data-auto-pageview="false"`，而不是 `data-auto-track="false"`。此配置要求 `v3.2.0` 或更高版本。

```html
<script
  defer
  src="https://your-umami.example.com/script.js"
  data-website-id="your-website-id"
  data-auto-pageview="false"
  data-performance="true"
></script>
```

Umami 将收集以下指标：

| 指标 | 衡量内容 | 良好阈值 |
| --- | --- | --- |
| **LCP**（最大内容绘制） | 主要内容出现所需的时间 | 2.5 秒或更短 |
| **INP**（交互到下一次绘制） | 用户交互时页面的响应速度 | 200 毫秒或更短 |
| **CLS**（累计布局偏移） | 页面加载时布局的稳定程度 | 0.1 或更低 |
| **FCP**（首次内容绘制） | 首个可见内容出现所需的时间 | 1.8 秒或更短 |
| **TTFB**（首字节时间） | 服务器开始响应的速度 | 0.8 秒或更短 |

## 第二步：查看性能数据

在 Umami 中打开网站并进入 **Performance**。您会看到：

- **指标卡片**显示每个指标的第 75 百分位（p75）。简单来说，大多数访客的数值都不超过这个数字。
- 根据 Google 阈值显示的**评分指示器**：绿色表示良好，黄色表示需要改进，红色表示较差。
- **页面明细**按页面 URL 显示性能。
- **环境明细**按浏览器、操作系统和设备类型显示性能。

## 第三步：识别缓慢页面

使用页面明细找出问题页面：

1. 按 **LCP** 排序，找出加载缓慢的页面。
2. 按 **CLS** 排序，找出存在布局偏移问题的页面。
3. 按 **INP** 排序，找出交互响应迟缓的页面。

## 第四步：诊断并修复问题

以下是常见情况：

### LCP（最大内容绘制）

大型图片、缓慢响应或阻塞渲染的资源会影响 LCP。尝试压缩图片、使用 WebP 或 AVIF，并预加载主要元素。

### INP（交互到下一次绘制）

运行时间过长的 JavaScript 和繁重的事件处理程序会影响 INP。尝试拆分长任务并简化开销较大的 UI 操作。

### CLS（累计布局偏移）

没有预留空间的图片或广告会影响 CLS。设置 `width` 和 `height`，为动态内容预留空间，并使用 `font-display: swap`。

## 第五步：跟踪改进

完成更改后，比较更改前后的日期范围。重点关注 p75 值。如果该值有所改善，说明大多数访客获得了更好的体验。
